# polestar-mcp v0.3.0

A read-only MCP server for the Polestar Data Portal M2M API: fifteen telemetry and charging
Domains, aggregate tools that answer real questions in one call, and an opt-in local history
store that gives a stateless API a memory.

Requires Node 20.6 or newer, and Polestar Data Portal credentials from
`data-portal.polestar.com`.

```bash
npm install -g polestar-mcp
mkdir -p ~/.config/polestar-mcp
printf 'POLESTAR_CLIENT_ID=...\nPOLESTAR_CLIENT_SECRET=...\nPOLESTAR_ACCOUNT_ID=...\n' > ~/.config/polestar-mcp/.env.secrets
chmod 600 ~/.config/polestar-mcp/.env.secrets
polestar-mcp
```

The Account ID is not the OAuth client ID. It is the value shown next to the Base URL in the
Data Portal, and it is sent as `x-client-id`; the gateway answers
`403 AUTHZ_CLIENT_ID_MISMATCH` when the two are confused, which is why the server asks for it
instead of guessing.

## What it offers

Twenty-six tools, all reads. `list_vehicles` and `list_domains` first, then one humanized
Domain tool each (`get_battery`, `get_target_soc`, and thirteen more), four aggregates
(`get_car_status`, `is_car_secure`, `get_needs_attention`, `get_charging_estimate`),
`plan_cheapest_charge` for cheapest-window planning against prices you supply, and
`polestar_status` so an agent can see the remaining allowance before it trips the guard.
Three history tools join when `POLESTAR_HISTORY_DIR` is set.

Domain data arrives summarized with the age of the underlying report, because a charge
setting can be days old while telemetry is minutes old. Pass `raw: true` for the untouched
payload. Failures come back as `isError` with a structured `code`, `httpStatus`,
`requestId` and a `hint` that names the variable to fix.

## Safety and limits

- Read-only by construction. Polestar publishes no v1 write endpoints, and this server
  registers none; `POLESTAR_ENABLE_WRITES` is the opt-in future writes would slot behind.
- `POLESTAR_ALLOW_LOCATION=false` refuses position at the request layer, so no quota is
  spent on it and it never reaches a result.
- A response labelled a different VIN or a different Domain is rejected rather than shown,
  because presenting one car's data as another's is the one failure this server will not
  commit.
- Delegation is allowlisted: `delegated_account_id` is honoured only for accounts listed in
  `POLESTAR_DELEGATED_ACCOUNT_IDS`, since the gateway accepts an unknown one quietly.
- Budget metering is fail-closed at 10,000 calls per day, with a 100 per minute ceiling
  waited out inside the request deadline. Background sampling is off unless
  `POLESTAR_SAMPLE` is set, and stands down at 80 percent of the daily budget.
- Streamable HTTP binds `127.0.0.1` unless told otherwise, and refuses a non-loopback bind
  without `POLESTAR_HTTP_TOKEN`. That token is a shared secret: everyone holding it can read
  every vehicle the credential can see.

Credentials live outside the project tree by default, and `npm run check-secrets` treats any
`.env`-family file inside it as a finding.

## Internal shape, if you are reading the code

`PolestarClient` is the deep module: token lifecycle, Envelope unwrapping, VIN resolution,
identity checks and the `DATA_NOT_AVAILABLE` to `null` rule. Below it a `Transport` seam with
two adapters, live HTTP with a deadline and a captured dump for offline work. Above it, tools
are declarative specs registered by one module, so a handler is callable from a test without
starting a server, and `src/domains.ts` is the single registry each Domain's route, scope,
cache lifetime, sampling decision and pinned key set come from.

## Verification

CI runs typecheck, build, the unit suite, coverage, both smoke modes, fixture integrity,
secret hygiene, tool-reference hygiene and four documentation gates. Each check prints a
success marker only after every assertion passes, and the ones that matter for absence scan a
positive control first, so green means the detector fired somewhere.
